# Xarmoured — Client Acquisition Launch Kit (v3)

This bundle contains **two deliberately separate deployment paths**:

1. **Existing application / CMS:** `xarmoured_initial_seed_v3_growth.sql` is the complete original v2 seed plus launch content, preserving the same `public.records` table. It adds/updates service SEO fields, homepage conversion content, 20 structured landing/resource/legal/FAQ pages, and 15 new FAQs. Do **not** run against production without a database backup and reviewing what it updates. The v3 script **replaces v2 deletion of five personal-research records with an unpublished/draft update**, preserving their content. Its upserts merge JSON data for the named records; key values explicitly supplied by the seed are still updated.
2. **Portable static website:** `/website/` is a fully rendered, responsive, SEO-ready multipage website with **26 actual indexable routes**, XML sitemap, robots.txt, semantic content and page-specific JSON-LD. It can replace an existing site only if you intentionally deploy it, and it is **not automatically connected to your Supabase admin CMS**. Content is bundled as HTML at build time.

The `content_manifest.json` and `build.py` allow a developer to integrate the copy with the existing frontend (or rebuild the static site). If you want to preserve the old site's functionality/design, use **path 1** and adapt the frontend to route the new content; do not blindly replace the production site with path 2.

## What this changes

- Four **defensible** published services: web, API, Android and retesting (no SOC/MDR or fabricated compliance credentials).
- Core commercial pages: About, Services, Methodology, Assessment, Contact, How We Work, Deliverables, Pricing, FAQs.
- Three buyer segments: SaaS/multi-tenant, ecommerce, startups.
- Five substantive articles: API authorization, assessment preparation, reports, retesting, Android testing.
- Visible calls to action and lead forms on `/contact/` and `/assessment/`.
- A sitemap containing only pages generated by this portable site; no fake client case studies, awards, certification badges or testimonials.
- Founder CVEs remain personal, **not** company-credited. The original company research feature remains unpublished.

## Setup the static website on Vercel

1. Copy or open the `website/` folder as the **Vercel project root**. Every actual page is `/<route>/index.html` (static rendering, not JavaScript-dependent). Vercel will recognize the `/api/lead.js` Node function.
2. Create a **Cloudflare Turnstile** widget for `xarmoured.tech`. Set the public site key in `website/assets/site-config.js`.
3. Verify the domain or sending address with **Resend**. Set server-only Vercel Environment Variables from `website/.env.example`: `TURNSTILE_SECRET_KEY`, `TURNSTILE_ALLOWED_HOSTNAMES`, `RESEND_API_KEY`, `CONTACT_TO_EMAIL`, `CONTACT_FROM_EMAIL`. The form **fails closed** until these are present.
4. Publish and test an actual enquiry to the inbox. Verify anti-abuse, errors, mail delivery and notification behavior. Confirm the live deployment environment supports Vercel Functions; static-only hosts won't execute `/api/lead`.
5. Route both `www` and apex to one canonical `https://xarmoured.tech/` origin. Use a permanent redirect from the other host.
6. Review the privacy policy and terms with your actual company status, email provider, data retention, jurisdiction and legal needs **before collecting visitor data**.

### Existing Supabase site

The seed assumes `public.records(module, title, slug, status, data, published_at, updated_at)` and a unique constraint on `(module,slug)`, matching the original. SQL stores page content, but you must confirm your existing frontend:

- Dynamically renders **published** page content and known paths; define explicit mappings for new slugs and nested `/resources/.../` and `/industries/.../` routes.
- Generates unique per-route `<title>`, meta description, canonical links, social meta tags and structured data from `seo_*` and `canonical_path` fields.
- Exposes **only published** CMS records publicly. Keep internal/admin API credentials server-side.
- Has a real server endpoint for leads, verifies Turnstile server-side and stores/sends leads privately. Do not expose a service-role key to a browser or permit public read on leads.
- Serves sitemap and robots entries that reflect **actual** live routes. If a route does not work, exclude it from the sitemap until implemented.

## SEO go-live checklist

- [ ] Live HTML for every public URL returns HTTP 200 with meaningful content **in initial HTML**; no important pages hidden behind client-only rendering.
- [ ] Unique title, description, self-referencing canonical and an accessible top-level `<h1>` per page.
- [ ] Clear links from home/services/resources to detailed pages. Test all internal links and 404s.
- [ ] `https://xarmoured.tech/robots.txt` and `/sitemap.xml` return 200 with correct canonical URLs.
- [ ] Homepage Organization, service Service and nested BreadcrumbList JSON-LD describe only verifiable facts.
- [ ] Real contact and assessment enquiry forms work end to end; simulate network failures and spam.
- [ ] Add the site to **Google Search Console** and **Bing Webmaster Tools**, verify ownership and submit the sitemap.
- [ ] Measure form conversions and relevant organic landing pages with privacy-respecting analytics. Do not create fake reviews or buy spam backlinks.
- [ ] Optimize PageSpeed and Core Web Vitals; ensure mobile nav and forms are usable.
- [ ] Publish real authorized case studies and technical research only when permission and correct attribution are secured.

**Do not expect SEO to automatically produce clients.** Organic visibility builds over time. Pair this site with targeted outreach, genuinely useful application security articles, and proof-backed client discussions.

## Security and operational notes

- Turnstile reduces bot abuse but does not replace durable rate limits, email filtering or operational monitoring. For higher traffic, use an edge/API gateway rate limiter and abuse detection.
- The serverless function validates inputs, escapes content, uses the Resend API, verifies Turnstile and does not expose secrets to the frontend. Inspect actual deployment headers, logs and error handling before launch.
- `privacy` and `terms` are drafts pending a human review. This is website content, not legal advice.
- V3 SQL is designed around the **provided v2 file**; no live database or current frontend source was available. SQL parse and route/link checks are possible here, but no live integration test against your DB or host is claimed.

## Rebuild the portable site

From a Python environment with `mistune` installed:

```sh
python build.py
```

`build.py` includes the original provided v2 baseline beside it, so rebuilds are self-contained. The generated website is deployable without Python.
