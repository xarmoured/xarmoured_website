What helps us estimate a project

  • Assessment type: Web application, API, Android app or focused retest.
  • Assets: Domains, application areas, endpoint count or build information. Do not send credentials or secrets in this form.
  • Complexity: User roles, tenants, authentication flows and integrations.
  • Environment: Staging versus production and any testing windows.
  • Timing: Target dates and any release dependency.
  • Goals: Security assurance, customer due diligence, recent changes or specific concerns.

What happens next

We review scope, clarify assumptions and decide whether the engagement is a fit. A quote and proposed rules of engagement follow only once requirements are understood. Form submission alone is not authorization to scan, test or exploit a system.

What not to send

Never include passwords, API tokens, production customer records or sensitive evidence in an initial enquiry. Use an agreed secure channel later in the process.
